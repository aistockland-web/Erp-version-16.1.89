## Dependency gate correction
The plugin ZIP contains no Composer/npm/Python/Go/Rust manifests, no lockfiles and no \`vendor/\` or \`node_modules/\` runtime tree. Bootstrap 5.3.8 is inventoried as a bundled CSS asset with its MIT notice, source identity and SHA-256. The production ZIP depends on the hosting WordPress/PHP runtime, which is not a package-manager dependency shipped in this ZIP.

Therefore:
- Dependency Review is **not applicable** to PRs that change no supported dependency manifest or lockfile.
- If such a manifest/lockfile is introduced or changed later, the high-severity dependency-review gate runs.
- The ZIP inventory remains blocking if a declared ecosystem lacks its matching lockfile, if a lockfile is orphaned, if a required Bootstrap declaration/license is absent, or if a vendored dependency directory appears without a lockfile.
- Five synthetic policy tests cover N/A, valid manifest/lockfile, missing lock, orphan lock, and untracked vendor directory cases.

This corrects a CI applicability defect; it does not claim a vulnerability scan of the hosting provider's PHP/WordPress runtime.

## WPCS finding review
The exact current scan artifact reported **57 errors, 266 warnings, 162 fixable entries**. These counts are not 455 vulnerabilities. Dominant findings are formatting/alignment, legacy class-file naming, and custom-capability recognition:
- All 138 \`WordPress.WP.Capabilities.Unknown\` warning instances map to 36 \`stockland_*\` capabilities declared in the canonical ERP role/capability source.
- The full WPCS JSON remains uploaded and visible for maintainability cleanup; it is not discarded.
- A separate blocker rejects new/unreviewed \`WordPress.Security.*\` and \`WordPress.DB.*\` findings. Exact source-contract tests review the five messages at their current locations.

### Reviewed SQL/cache findings
\`includes/rest/class-rest-wholesale.php\` uses a wrapper that passes SQL through \`$wpdb->prepare($sql, $args)\`, rejects a failed/empty prepared result, and executes only the prepared string. SQL table identifiers use \`%i\`; the optional SKU uses \`%s\`; generated IN lists contain only \`%d\` placeholders with integer-derived IDs. Any uncertain query result fails closed. The live inventory/transaction reads are intentionally uncached because stale stock/reservation values could overstate wholesale surplus. Adding object caching merely to silence PHPCS would weaken consistency.

### Reviewed exception/output finding
\`includes/class-stockland-payroll-statutory.php\` returns a fixed catalogue of compensation-validation messages. The flagged \`$validation_error\` is placed into a \`RuntimeException\` for the API error path, not echoed into HTML directly. The source-aware gate checks the fixed-message helper and rejects new unreviewed security/database findings or moved locations.

These are explicit, version-specific contextual reviews—not blanket disables for security rules in future code. Any new occurrence, changed line or source shape fails the gate and requires review.
