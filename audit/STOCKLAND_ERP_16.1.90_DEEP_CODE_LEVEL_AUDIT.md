## Findings addressed

1. **Exception encoding was at the wrong layer.** The HR/Payroll REST path serializes validation exception text into a JSON error response, while the existing browser toast inserts it with `textContent`. HTML-escaping values before serialization risks users seeing encoded entities. Dynamic employee/effective-date/treatment values are now sent as plain text in the REST error message; browser rendering remains text-only. No HTML output or raw HTML injection is introduced.
2. **PHPCS source-formatting baseline.** Reviewed formatting corrections are applied only to payroll statutory validation, the System Health diagnostic and wholesale advisory code.
3. **Custom capabilities were misclassified as unknown.** The dedicated source-analysis ruleset declares only the 36 capability identifiers already present in the established role/capability implementation. No capability or role access is added.
4. **REST controller filenames were flagged even though they are loader contracts.** Only the specific legacy filename sniff is suppressed in each of the 18 already-loaded REST controller files. No file is renamed.
5. **Wholesale SQL findings were triaged at the use sites.** SQL values continue to be separately prepared, dynamic table identifiers use the existing identifier placeholders, and the authoritative live stock/commitment read remains uncached to avoid serving stale data.

## Behaviors deliberately unchanged

- No schema migration; no insert/update/delete of ERP business records.
- No SKU or variant identity changes, no inventory history/effective-date rewrite, and no unlocking or alteration of inventory records.
- No immutable stock ledger, audit-chain, GL/PLEDGER, purchase/receiving, reservation, transfer, approval or SOP transition change.
- No payroll formula, pension, PAYE band, role capability ID or capability migration change.
- CSS source modules, compiled CSS, Bootstrap 5.3.8, JavaScript, PWA assets and original logos stay byte-for-byte as in 16.1.89. The release/cache identity changes so browsers request current release assets; this is not a visual restyle.
- Existing production functions and actions remain wired; test gates cover payroll/Health, notifications, browser payroll preview, release invariants, CSS parsing and the PHPCS security/database gate.
